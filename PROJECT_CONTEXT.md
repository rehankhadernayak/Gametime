## 1. What Is Gametime

A Singapore family app where **children (ages 6–13) earn gaming credits by completing chores and homework**. Parents set tasks → children submit photo/video evidence → Claude Vision reviews it → parents approve → children earn points → children redeem for Roblox, Steam, Razer Gold, and gaming time.

**Two currencies:**
- **RP (Reward Points)** — earned by completing tasks; spent on gaming time and custom rewards
- **GP (Giftcard Points)** — funded by parents via wallet top-up; spent on real digital gift cards

## 2. Architecture

```
┌─────────────────────────────────────────────────────────────┐
│  backend/          Node.js + Express + SQLite               │
│  (port 4000)       ES modules only (import/export)          │
├─────────────────────────────────────────────────────────────┤
│  frontend/         React 18 + Vite                          │
│  (port 5173)       Plain CSS custom properties, no UI lib   │
├─────────────────────────────────────────────────────────────┤
│  mobile/           React Native + Expo SDK 51               │
│                    Expo managed workflow, iOS + Android      │
└─────────────────────────────────────────────────────────────┘
```

All three layers talk to the same backend. Mobile reads API URL from AsyncStorage (runtime-configurable via ApiSettingsScreen).

## 3. Tech Stack

| Layer | Tech | Key Notes |
|---|---|---|
| Backend runtime | Node.js, Express | **ES modules** — `import/export` only. Never `require()`. |
| Database | SQLite via `sqlite3` + async `sqlite` wrapper | `better-sqlite3` is NOT used. All DB calls are async/await. |
| Auth | JWT + bcryptjs | httpOnly cookies on web; expo-secure-store on mobile |
| Logging | Pino + pino-http | Never `console.log` in backend. Use `logger` from `utils/logger.js`. |
| Validation | Zod | All new routes must validate with Zod |
| AI | Anthropic SDK, model `claude-sonnet-4-6` (default) | Override via `CLAUDE_MODEL` env var. Vision review + streaming chat + insights. Falls back to local scoring rules if API key absent. |
| Giftcards | Athena API | Mock mode on (`ATHENA_MOCK_MODE=true`, `ATHENA_ENABLED=false`) |
| Email | Nodemailer | Needs real SMTP env vars — currently preview mode only |
| Push | Expo push notifications | Wired but needs Expo project credentials to fire |
| Frontend | React 18, Vite, CSS custom properties | Font: Inter (body) + Sora (headings). No Tailwind, no MUI. |
| Mobile | Expo SDK 54, React Navigation 7 (Drawer + Stack) | `expo-secure-store` for token, `expo-image-picker` for evidence |
| Rate limiting | `express-rate-limit` | Per-endpoint limiters in `routes/` |
| Error handling | Centralized `middleware/errorHandler.js` | Never throw unhandled — always use `next(err)` |

## 5. Database Schema

All schema changes go in `backend/src/db/init.js` using `ensureColumn()` / `ensureTable()`. **Foreign keys are ON.** The DB connection uses the async `sqlite` wrapper — not `better-sqlite3`. All DB calls need `await`.

### Core Tables

```sql
-- Parents
parent_accounts (
  id TEXT PRIMARY KEY,
  name TEXT, email TEXT UNIQUE, password_hash TEXT,
  gp_balance INTEGER DEFAULT 0,                    -- GP wallet (cents)
  notification_preferences TEXT,                   -- JSON blob, nullable
  created_at TEXT
)

-- Children (age-gated: PIN for ≤9, email+pass for ≥10)
child_profiles (
  id TEXT PRIMARY KEY,
  parent_id TEXT → parent_accounts,
  name TEXT, date_of_birth TEXT,
  email TEXT UNIQUE,            -- optional, for age ≥10
  password_hash TEXT,           -- optional, for age ≥10
  pin_hash TEXT,                -- optional, for age ≤9
  points_balance INTEGER DEFAULT 0,           -- RP
  giftcard_points_balance INTEGER DEFAULT 0,  -- GP (cents)
  created_at TEXT
)

-- Tasks
tasks (
  id TEXT PRIMARY KEY,
  parent_id TEXT → parent_accounts,
  child_id TEXT → child_profiles,
  title TEXT, description TEXT,
  points INTEGER,        -- RP reward
  gp_points INTEGER,     -- GP reward (cents)
  state TEXT,            -- Active | Expired | Deleted
  category TEXT,         -- study | chore | fitness | creative | other
  recurrence_days TEXT,  -- comma-separated day numbers e.g. "1,3,5"
  due_date TEXT,         -- ISO 8601, max 7 days out
  created_at TEXT
)

-- Task Completions (one per approval cycle)
task_completions (
  id TEXT PRIMARY KEY,
  task_id TEXT → tasks,
  child_id TEXT → child_profiles,
  status TEXT,            -- PendingApproval | Approved | Rejected | Disputed
  evidence_data TEXT,     -- base64 data URL (legacy) or file path
  evidence_mime TEXT,     -- image/jpeg | video/mp4 | etc.
  evidence_type TEXT,     -- photo | video
  evidence_note TEXT,     -- child's submission note
  parent_note TEXT,       -- parent's rejection/approval note
  ai_recommendation TEXT, -- Approve | Reject | NeedsParentReview
  ai_confidence INTEGER,  -- 0–100
  ai_reason TEXT,
  ai_model TEXT,
  ai_analyzed_at TEXT,
  ai_status TEXT,         -- Completed | Unavailable | Error | Pending
  disputed BOOLEAN DEFAULT 0,
  dispute_note TEXT,
  disputed_at TEXT,
  resolved_at TEXT,
  completed_at TEXT
)

-- Gaming
gaming_settings (
  id TEXT PRIMARY KEY,
  parent_id TEXT UNIQUE → parent_accounts,
  points_unit INTEGER DEFAULT 10,     -- RP per unit
  minutes_unit INTEGER DEFAULT 30,    -- gaming minutes per unit
  daily_cap_minutes INTEGER DEFAULT 120,
  weekly_cap_minutes INTEGER DEFAULT 600
)

gaming_games (
  id TEXT PRIMARY KEY,
  parent_id TEXT → parent_accounts,
  name TEXT, platform TEXT,
  status TEXT  -- Blocked | Allowed
)

gaming_sessions (
  id TEXT PRIMARY KEY,
  child_id TEXT → child_profiles,
  parent_id TEXT → parent_accounts,
  game_name TEXT, platform TEXT,
  requested_minutes INTEGER,
  duration_minutes INTEGER,
  status TEXT,        -- Started | Completed | Denied
  denial_code TEXT,   -- BLOCKED_GAME | DAILY_CAP_REACHED | etc.
  started_at TEXT, ended_at TEXT
)

-- Rewards & Redemptions
rewards (
  id TEXT PRIMARY KEY,
  parent_id TEXT → parent_accounts,
  child_id TEXT → child_profiles,  -- null = available to all children
  title TEXT, description TEXT,
  cost INTEGER,          -- RP or GP cost
  points_type TEXT,      -- RP | GP
  qty_limit INTEGER,     -- null = unlimited
  created_at TEXT
)

redemptions (
  id TEXT PRIMARY KEY,
  reward_id TEXT → rewards,
  child_id TEXT → child_profiles,
  status TEXT,           -- Pending | Fulfilled | Cancelled
  points_type TEXT,      -- RP | GP
  points_spent INTEGER,
  fulfilled_at TEXT,
  created_at TEXT
)

points_transactions (
  id TEXT PRIMARY KEY,
  child_id TEXT → child_profiles,
  parent_id TEXT → parent_accounts,
  delta INTEGER,          -- positive = earned, negative = spent
  points_kind TEXT,       -- RP | GP
  reason TEXT,
  created_at TEXT
)

-- Giftcards (Athena integration)
giftcard_inventory (
  id TEXT PRIMARY KEY,
  parent_id TEXT → parent_accounts,
  batch_id TEXT,
  brand TEXT, denomination TEXT,
  code TEXT (encrypted), pin TEXT (encrypted), expiry_date TEXT,
  status TEXT,    -- Available | Reserved | Redeemed
  reward_id TEXT → rewards,
  redeemed_by TEXT → child_profiles,
  created_at TEXT
)

-- Notifications
notifications (
  id TEXT PRIMARY KEY,
  recipient_type TEXT,   -- Parent | Child
  recipient_id TEXT,
  type TEXT,             -- task_submitted | task_approved | task_rejected | etc.
  title TEXT, message TEXT,
  read BOOLEAN DEFAULT 0,
  data TEXT,             -- JSON metadata for deep linking
  created_at TEXT
)

device_tokens (
  id TEXT PRIMARY KEY,
  recipient_type TEXT, recipient_id TEXT,
  token TEXT UNIQUE,
  platform TEXT,  -- ios | android | web
  created_at TEXT
)

-- AI Chat
ai_messages (
  id TEXT PRIMARY KEY,
  parent_id TEXT → parent_accounts,
  role TEXT,     -- user | assistant
  content TEXT,
  created_at TEXT
)

-- Session revocation (checked by auth middleware on every request)
sessions (
  id TEXT PRIMARY KEY,
  user_id TEXT,           -- parentId or childId
  role TEXT,              -- parent | child
  expires_at TEXT,        -- ISO 8601
  created_at TEXT
)
-- auth.js verifies: SELECT FROM sessions WHERE id=? AND expires_at > now

-- Auth Security
failed_login_attempts (
  id TEXT PRIMARY KEY,
  email TEXT,
  attempted_at TEXT,
  ip TEXT
)
-- Purged on boot: DELETE WHERE attempted_at < now - 1 hour

-- Giftcard ↔ Reward link (allows auto-fulfillment on redemption)
reward_giftcard_links (
  reward_id TEXT → rewards,
  batch_id TEXT,          -- links to giftcard_inventory batch
  created_at TEXT
)

-- Task Requests (child → parent)
task_requests (
  id TEXT PRIMARY KEY,
  child_id TEXT → child_profiles,
  parent_id TEXT → parent_accounts,
  title TEXT, description TEXT,
  requested_points INTEGER,
  status TEXT,      -- Pending | Approved | Rejected
  parent_note TEXT,
  created_at TEXT
)
```

## 7. Auth Flow

```
Parent login  → POST /auth/login → JWT in httpOnly cookie (web)
                                 → JWT in expo-secure-store (mobile)
                                 → GET /auth/me to hydrate role + user object

Child login   → 3 methods:
  1. Parent session  → POST /auth/child-login (parent impersonates)
  2. Email/password  → POST /auth/child-login-direct
  3. PIN (age ≤9)    → POST /auth/child-login-pin (parentEmail + childName + PIN)

req.auth      → { parentId, childId, role: 'parent'|'child', sessionId, ... }
Role gates    → if (req.auth.role !== 'parent') return res.status(403)...
Brute-force   → 5 failed attempts = 15-minute lockout per email
Session check → auth.js looks up sessions table on EVERY request — revoked sessions return 401
Token sources → Authorization: Bearer <token>  OR  gametime_token cookie (web)
```

## 10. AI Pipeline

### Evidence Review (automatic on task submission)
1. Child submits task completion with photo/video
2. `taskService.js` calls `aiReviewService.js` asynchronously (non-blocking)
3. Claude Vision analyses evidence + task description
4. Updates `task_completions` with: `ai_recommendation`, `ai_confidence`, `ai_reason`, `ai_status`
5. Parent sees recommendation in approvals screen

### Parent AI Assistant (streaming)
- Model: `claude-sonnet-4-6` (default, override via `CLAUDE_MODEL` env var)
- Tools available to Claude: `get_family_overview`, `create_task`, `create_reward`
- Chat history persisted in `ai_messages` table (parent_id scoped)
- SSE event types: `text` (delta), `tool_start`, `tool_done`, `done`, `error`
- Greeting sent once on first login (checks if already sent before calling `/ai/greet`)
- Signup flow: exposes `finalize_signup` tool → emits finalize event with response data

### Child Study Buddy
- Separate endpoint `/ai/child/chat`
- Tools: `get_my_stats` (live child stats), `start_break_timer` (triggers UI modal on client)
- Break timer types: `eye_rest` (20-20-20 rule), `study_break`, `stretch`, `water`, `custom`
- Age-appropriate tone, no chat history persistence (session-only)

### Evidence Review Local Fallback
- `aiReviewService.js` has a full scoring engine that runs when `ANTHROPIC_API_KEY` is absent
- Scoring: 0.45 base + evidence present (+0.2), type match (+0.1), note quality, keyword overlap
- Thresholds: score ≥0.7 → Approve | ≤0.28 → Reject | middle → NeedsParentReview
- Model field set to `local-rules-v1` when fallback is used

### Family Insights
- `GET /ai/parent/insights` → Claude analyses per-child gaming + task data
- Returns: narrative string + per-child confidence score (0–100) + stats
- Health bar: green ≥70, amber 40–69, red <40

## 13. Important Gotchas

| Gotcha | Rule |
|---|---|
| `env.js` cannot import `logger` | Circular dep. Use `process.stderr.write()` instead. |
| `better-sqlite3` not used | DB uses async `sqlite` wrapper. Always `await db.run/get/all`. |
| ES modules only | No `require()`. No `module.exports`. No `__dirname` (use `fileURLToPath`). |
| Hot SQLite backup only | Never `cp` a live SQLite file. Use `db.driver.backup(dest, cb)`. |
| notifInitialised must be `useRef` | If it were `useState`, would cause extra render → premature auto-save on load. |
| Children always pass `shouldNotify` | Preference gating is parent-only. Child recipients always receive notifications. |
| `pino-http` excludes `/health` | `autoLogging: { ignore: (req) => req.url === '/health' }` — prevents log spam. |
| Mobile SSE via XHR | `EventSource` not available in Expo Go. Use `utils/sse.js` (XHR + readyState polling). |
| Evidence base64 vs file path | Legacy = base64 data URL stored in DB. New = file path. `evidence_data` holds either. |
| 10MB evidence limit | Enforced in both TaskCompletionForm (frontend) and ChildTasksScreen (mobile) + backend. |
| Evidence route order in tasksRoutes.js | `GET /tasks/evidence/:completionId` must be registered BEFORE `/:taskId` param routes or it gets captured. |
| Webhook route before JSON parser | Athena webhook needs raw body for HMAC validation. It's registered before the JSON body-parser in `app.js`. |
| Rate limiter is in-memory | Uses a Map (not Redis). Won't survive restarts, not safe for multi-process/cluster deployments. |
| Session revocation on every request | `auth.js` queries the `sessions` table on each authenticated request. Deleting a session row immediately invalidates that token. |
| AI parent tools (actual list) | Only 3 tools wired in `aiService.js`: `get_family_overview`, `create_task`, `create_reward`. The CLAUDE.md list was aspirational — verify before adding more. |
| cryptoService format | Encrypted strings format: `<ivHex>:<tagHex>:<ciphertextHex>`. AES-256-GCM, 12-byte random IV, SHA-256 key derivation. |
| constants.js for all enums | Never hardcode state strings. Import from `utils/constants.js`: `TASK_STATES`, `DENIAL_CODES`, `POINTS_KINDS`, `EVIDENCE_TYPES`, `GAME_STATUSES`, etc. |
| Email verification on signup | `emailExistenceService.js` does an SMTP probe (RCPT TO) during signup. Test domains (example.com, localhost) always pass. Disable with `EMAIL_CHECK_MODE=none`. |
